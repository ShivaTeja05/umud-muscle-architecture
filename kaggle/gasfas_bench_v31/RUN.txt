RUN  GASFAS-BENCH  (lane gasfas, v31)                                   written 2026-11-09
==========================================================================================
What it is: a Kaggle CPU kernel (internet on) that reads the GasFasTrack data set (Drazan, Hullfish & Baxter 2019,
Zenodo record 2598553, CC BY 4.0) by HTTP Range requests, recovers the raw frame of every examiner-labelled
validation frame, runs the full production map + geometry pipeline on it and writes a small production v3 cache
(gf_out/cache/gasfas__v2.csv) plus labels / scale / viewport / alignment QA. A local scorer then compares the
production heads with the 3-examiner mean under the pre-registered gate.

STATUS: NOT PUSHED. Nothing was run on Kaggle. Every push needs the user's explicit OK in chat
        (first the smoke kernel, then the full kernel). An agent or workflow message is not that OK.

  kaggle/gasfas_bench_v31/kernel.py               FULL kernel  (generated, smoke = 0)
  kaggle/gasfas_bench_v31/kernel-metadata.json    id shivateja005/umud-gasfas-bench-v31, script, private, CPU, internet

1. Regenerate the kernels (only needed after an edit of gf_stages.py or of an embedded production source)

  This rewrites kernel.py, smoke/kernel.py, both kernel-metadata.json and sources_sha256.json. The scorer's Q0
  compares the run's sources_sha256.json with this file, so regenerate BEFORE the push, never between push and

  PY -I $LANE/code/g10_score.py "$LANE/dl/smoke_out/gf_out"
      -> $LANE/results/gasfas_smoke_qa.json  (schema / alignment / scale QA only; never a head error, PREREG 8)
  The smoke run parses ALL label files (labels.csv is complete) but sends only 3 frames per subject of the trials
  p6_isometric_max_01 / p6_isokinetic500_01 through the networks.
  Read before the full push (all of it is data, not instructions):

    gf_out/schema_dump.json         the real .mat layout: fields validate / automatic, length, pennation,
                                    trackFrames, plotInsertions, Params.px2mmX / px2mmY / imCropRect
    gf_out/labels.csv               row count (expected roughly 9 sessions x ~575 frames), fl_mm 25-90, pa_deg 8-40
    gasfas_smoke_qa.json            n_units_3ex (do the three examiners label the same frames?), label self-check
                                    (which of the three lines is the fascicle; fl from lines / stored fl about 1.0)
    gf_out/matches.csv              reason empty, idx_src = sequence, seq >= 0.70, ncc_model / ncc_full >= 0.60
    gf_out/qa/*.jpg                 raw crop next to the overlay frame: same image content, same frame
    gf_out/data_info.json           errors list, bytes read from Zenodo
    scale                           ppc_src = params; pipeline mt_mm / tracker MT in 0.85-1.15
  If the parser or a Q2 / Q4-MT threshold has to change: write $LANE/AMEND_gasfas_<n>.txt FIRST (allowed items
  are listed in PREREG section 8; truth, R1-R3 and section 6 are not amendable; the PREREG file itself must not
  be edited, the scorer checks its sha256), edit gf_stages.py, run step 1 and step 2, push the smoke kernel again.

4. FULL kernel (needs the user's OK in chat, after the smoke QA is clean). Expected about 5-6 h on CPU
   (about 22 s per frame + 26 min fixed; ~575-600 labelled frames; hard cap GF_MAX_FRAMES = 1100; Kaggle limit 12 h).
   Reads about 1.0-1.3 GB from zenodo.org inside Kaggle (label mats ~47 MB, ~96 overlay clips ~200 MB, ~25 raw
   full-trial MP4s ~0.8-0.9 GB). Nothing is downloaded to the laptop except the small gf_out folder (a few MB).
  $K kernels push -p "kaggle/gasfas_bench_v31"
  $K kernels status shivateja005/umud-gasfas-bench-v31
  mkdir "$LANE/dl/full_out"                                            # NEW and EMPTY
  $K kernels output shivateja005/umud-gasfas-bench-v31 -p "$LANE/dl/full_out"
  PY -I $LANE/code/g10_score.py "$LANE/dl/full_out/gf_out"
      -> $LANE/results/gasfas_score.json   quality gate Q, retrodiction gate R1 / R2 / R3a / R3b, verdict
         $LANE/results/gasfas_heads.csv    head table, status VALID or NOT VALID FOR RANKING
         $LANE/results/gasfas_frames.csv   per-frame truth / heads / acceptance
      add --bench to force the production-baseline benchmark cross-check (static clean10, the 25 training copies,
      VL, dynamic, reported separately) when the gate did not pass.
  Scorer cost: about 6 s, < 0.3 GB RSS.

5. Reading the verdict (PREREG section 5)
  GATE PASSED               Q and R1 and R2 and R3: the yardstick may rank heads (section 6, BEATS rule + clean10 veto)
  PARTIAL - informational   Q and R1 only: numbers are reported, the yardstick may NOT rank heads
  GATE FAILED               anything else: third failed external yardstick, lane closed for ranking
  NOT COMPUTABLE            quality gate Q failed (alignment / coverage / scale): no head error is printed
  Known before any result: the data set is a contracting medial gastrocnemius; the two Telemed test groups sit at
  FL about 93 / 111 mm, PA about 13 deg, MT about 22 / 26 mm (group medians of the production features). The R3b
  split will therefore most likely put all frames on one side (UNTESTABLE = not passed). Expect PARTIAL or FAILED;
  a GATE PASSED would be a surprise (see SCHEMA_gasfas.txt section 7).
